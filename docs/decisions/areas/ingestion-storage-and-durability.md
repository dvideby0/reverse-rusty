# Ingestion, storage & durability decisions

> [Architecture decision hub](../../DECISIONS.md)

Write paths, segments, WAL and source persistence, compaction, recovery, and durable mutation semantics.

| ADR | Decision | Summary | Status |
|---|---|---|---|
| [004](../adr-004-lsm-write-path.md) | LSM write path over full rebuild | Log-structured writes (immutable segments + memtable + tombstones, atomic epoch swap) instead of full rebuild — ~750k updates/sec/core, immediate visibility. | Accepted |
| [009](../adr-009-score-based-compaction.md) | ClickHouse-style score-based compaction | Score-based greedy compaction (not RocksDB leveled) because percolation must probe *every* segment — directly minimizes time-integrated segment count. | Accepted |
| [012](../adr-012-mmap-segment-format.md) | mmap'd segment file format + frozen hash tables | Custom `.seg` format with frozen open-addressing hash tables, mmap'd for zero-copy reads; the precondition that makes the anchor skip-filter pay off. | Accepted |
| [013](../adr-013-write-ahead-log.md) | Write-ahead log (WAL) for crash recovery | Append-only CRC-framed WAL for the memtable; WAL-first (durability before visibility), a failed append rejects the write, fsync policy configurable. | Accepted |
| [014](../adr-014-query-source-store.md) | Engine-level query source store | Keep original query text in an engine-level `sources.dat` (not in `.seg`), so source text never touches the match hot path. | Accepted |
| [016](../adr-016-snapshot-read-path-arcswap.md) | Snapshot read path (ArcSwap) over RwLock | Lock-free reads via `ArcSwap<EngineSnapshot>` + write-only `Mutex`; structural sharing makes publish O(1) (PUT 82 ms → ~2 µs at 1M queries). | Accepted |
| [017](../adr-017-durable-bulk-ingest.md) | Durable bulk ingest (segment = artifact, manifest = commit) | Bulk ingest is durable-or-rejected (RocksDB IngestExternalFile model); no silent in-memory fallback, manifest write is the atomic commit point. | Accepted |
| [018](../adr-018-bulk-ingest-per-item-outcomes.md) | Bulk ingest reports per-item outcomes (ES-style) | `/_bulk` returns per-item statuses (which queries were dropped + why), not just an aggregate count. | Accepted |
| [020](../adr-020-resident-memory-reduction.md) | Production-scale resident-memory reduction | Lazy on-disk source store + flat logical-index columns cut resident memory ~148 → ~96 B/query (→ ~4.5 with both, opt-in) ahead of sharding. | Accepted |
| [051](../adr-051-fail-closed-flush-compaction.md) | Fail-closed flush, compaction & reseal | Extend ADR-017's durable-or-rejected discipline to flush/compaction/reseal/recompile: build the replacement durable before destroying what it replaces, gate WAL-advance/file-deletion on the commit point. No silent restart data loss on disk failure. | Accepted |
| [056](../adr-056-compaction-reanchoring.md) | Compaction-that-improves (re-anchoring drifted queries) | Opt-in `compaction_reanchor`: a merge re-derives each alive query's cover with current frequencies (decoding the stored SoA, reusing `anchor_plan`) so a drifted anchor moves to a more-selective one — shrinking hot postings + fan-out. FN-safe by the `anchor_plan`/`match_into` matched pair (SoA copied verbatim); a no-op in a cluster (frozen dict); default-off ⇒ byte-identical. Closes the Tier-2 item. | Accepted |
| [057](../adr-057-frozen-dict-format-versioning.md) | Version + harden the frozen-space serializations (feature dict + tag dict) | Add a `magic + version` header (`RDCT`/`RTGD`) to the two previously-unversioned binary formats so a layout change or newer-build blob fails loud instead of misparsing; strict `dict::kind_from_tag` decode (unknown tag ⇒ error, never silent `Generic`); fully-fallible parse (no panic on truncation). Legacy header-less blobs still read; content-based fingerprint untouched ⇒ gRPC handshake byte-identical. Closes the "dict format not versioned" robustness item. | Accepted |
| [066](../adr-066-tombstone-durability-at-commit.md) | Tombstone durability at the commit point | Fixes two pre-existing single-node bugs found building the ADR-064 upsert: (1) base-segment deletes lived only in the in-RAM mmap overlay + their WAL frames, so the flush-time WAL reset **resurrected** acknowledged deletes on reopen (default-config reproducible); (2) compaction renumbers `(seg_idx, local)` while stale positional WAL frames remain, so a crash replay could **tombstone the wrong query** — a zero-FN violation. Fix: per-segment dead-locals roaring bitmaps in Manifest **v3** (the Lucene `.liv` analogue), applied on open before WAL replay; the production delete logs ONE address-free `DeleteByLogical` frame (WAL **v3**) replayed through the live path's funnel; a manifest `wal_seq_watermark` skips stale base-positional frames. v1/v2 manifests + v1/v2 WALs read back unchanged. | Accepted |
| [121](../adr-121-atomic-source-sidecar-commit.md) | Atomic manifest-selected source-sidecar commits | Engine-manifest v7 selects an fsync'd immutable source generation in the same atomic commit as the segment registry. Bulk rejects before commit on source failure; flush retires the WAL only after the joint commit; reopen automatically completes a crash between manifest rename and live source publication. Backup copies and requires exactly the selected sidecar. | Accepted |
| [122](../adr-122-fail-closed-positional-tombstones.md) | Fail-closed positional tombstones | Replace reconstructable `(segment, local)` calls with a process-local `SegmentAddress` carrying opaque segment generation + logical identity; validate generation/local/identity/liveness before the WAL. Stale/dead tokens return typed `TombstoneError` variants and append nothing, while valid mutations remain WAL-first. Recovery stays idempotent for historical frames. | Accepted |
