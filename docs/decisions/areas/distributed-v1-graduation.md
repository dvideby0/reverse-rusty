| [070](../adr-070-cluster-rest-surface.md) | Cluster REST surface — the coordinator-mode server | ADR-065 criterion 1 (the first of the three that unblock testing everything else): a **coordinator mode** inside the existing `server` binary (`--cluster`) — one REST dialect, two backends, shared auth/request-id/metrics middleware (a `RequestCtx` seam). In-process (`--shards K`, durable build/reopen via `cluster_exists` → `open`) on the default build; remote (`--shard-endpoint primary[,replica…]`, dict + tag space minted by the extracted `freeze_feature_space` pass A and shipped at connect) under `distributed`. Honest deltas: no-cluster-analogue surfaces answer **501 with the alternative**, unsupported request features (`rank` → criterion 5, `explain`) are **400s never silently ignored**, `GET /_doc` works on local clusters via a new `Shard::source_of` (default = loud error, so a remote shard can't fake "not found"). Remote coordinator is stateless (durability = the shard nodes' translogs; deterministic dict re-mint keeps the ADR-034 handshake green across coordinator restarts). Proven: clog round-trip/torn-tail, coordinator upsert units (created/updated/moved/never-deletes/fail-closed), the durability oracle's upsert module (log-tail AND checkpoint reopen ≡ pre-crash ≡ brute), and cluster handler tests over a real in-process cluster (CRUD/bulk/filtered search/include_broad/vocab alias both-forms/cluster ops/501+400 contracts). | Accepted |
| [071](../adr-071-grpc-tls-auth.md) | TLS + mesh auth on the gRPC transports | ADR-065 criterion 2: both gRPC surfaces (shard `ShardService` + control-plane `ControlService`) gain two independent, opt-in knobs — **TLS** (tonic `tls-ring`/rustls; operator PEM identity server-side, CA + optional domain override client-side; mTLS deferred — node admission is the token's job at v1) and a **mesh token** (ONE shared cluster secret, `--cluster-token`/`RR_CLUSTER_TOKEN`, ADR-062 validation rules) attached to every RPC as `authorization: Bearer` metadata and verified constant-time BEFORE any handler (the interceptor wraps the whole service ⇒ default-deny covers future RPCs). One `cluster::security` module serves both transports and both sides (client inject / server verify), so the planes can't drift; `RemoteShard` + the Raft network client store interceptor-wrapped channels (zero RPC-call-site churn); additive `_with_security` constructors keep every unset path byte-identical; the coordinator RETAINS its `ClientSecurity` so internal connects (peer recovery, live handoff) ride the same TLS + token. Config is fail-loud (malformed PEM/token refuses startup; token-without-TLS warns loud). Trust model documented: token = mesh admission, TLS = server auth + wire privacy; the HTTP token (ADR-062) stays separate (different audiences/rotation). deny policy: ISC allowed (the rustls/ring chain) and the gate's `cargo deny` widened to `--all-features` so the distributed supply chain is policy-checked. Proven: secured K=2 cluster ≡ brute incl. dict shipping + live writes over TLS+token; wrong/missing token + plaintext-client-to-TLS-server all fail LOUD (never an empty result); a secured 3-node control plane elects + quorum-commits; security-module units (validation/inject/verify round trip). In-test certs via `rcgen` (dev-dep — no key material in the repo). | Accepted |
| [072](../adr-072-multi-machine-harness.md) | The multi-machine test harness — containers, kill-and-recover, handoff under load | ADR-065 criterion 3 (the last unblocking item): a compose-based harness (`deploy/`) exercising the **fully secured** stack (ADR-071 TLS + token) through the **public surfaces only** (the ADR-070 coordinator REST + node bins) across real container network boundaries — the failure class localhost oracles structurally cannot reach (process lifecycle, reconnects, startup ordering, container filesystems). Deferred: multi-host topologies (same images, criterion 10's runbook), partition/latency/disk fault injection, control-plane→coordinator wiring (the ADR-048 deployment-maturity note). | Accepted |
| [074](../adr-074-tagged-cluster-vocab-change.md) | Tagged-cluster vocabulary change — TagId carry-through | ADR-065 criterion 4 (the ADR-055 deferral): `set_vocab`/`learn_and_apply` now work on a **tagged** cluster instead of refusing. Mechanism = **carry stored `TagId`s through the blue/green rebuild verbatim** (the single-node ADR-049 precedent), NOT the hypothesized raw-string persistence: the tag space is orthogonal to vocabulary and preserved (the rebuild re-mints the *feature* dict, never the `TagDict`), interned ids keep their dense slots and synthetic ids are deterministic hashes — so id carry-through is byte-identical reconstruction with zero new durable state, no manifest bump, no synthetic-string side table, and ADR-049's "tag strings die at the boundary" intact. `Engine::live_sources_tagged` + a `Shard::live_sources_tagged` seam gather `(logical, dsl, tag_ids)` per shard; `PlacedQuery.tag_ids` carries them through re-placement (an alias can move a query's shard — its tags travel); the wire stays dict-agnostic (`RemoteShard` refuses non-empty `tag_ids` loudly). The `tags_present` latch demotes to `/_stats` introspection — it was also lossy (a checkpointed synthetic-only cluster restores it `false`, so the old guard would have silently dropped tags after reopen; closed structurally). **Two pre-existing sources-durability bugs found by the new oracle, both fixed:** cluster bulk ingest never wrote `sources.dat` (a checkpointed+reopened cluster gathered an EMPTY corpus — `set_vocab` rebuilt to zero queries), and a clean-shard checkpoint skipped the sources rewrite (a deleted query's source went stale on disk — `set_vocab` after reopen would RESURRECT it). Fixed at both commit points (bulk seal + checkpoint seal, fail-closed per ADR-051). Oracle-proven: K-swept tagged rebuild ≡ brute-with-tags (interned + synthetic, filtered ⊆ unfiltered, re-placed query keeps tags), checkpoint → reopen → rebuild → reopen, the latch-blind-spot + both sources regressions, the wire guard. Non-local + multi-word refusals (ADR-061) stand. | Accepted |
| [075](../adr-075-cluster-ranking.md) | Cluster ranking — rank-at-shard, merge at the coordinator | ADR-065 criterion 5 (the ADR-059 deferral): the `rank` block works in cluster mode. **Rank-at-shard + compile-once-fan** (the ADR-055 pattern; ES query-then-fetch shape): the coordinator compiles the spec ONCE against the ONE shared frozen `TagDict` (`compile_rank_spec`, same `get_or_synthetic` as the filter), a new required `Shard::percolate_filtered_ranked` fans the same `&CompiledRankSpec` to every probed shard, each shard scores its OWN matched ids against its tag columns under ONE snapshot (per-shard newest-live-copy, the single-node semantics), and the coordinator merges + dedups by id — safe because copies of a logical are version-identical across shards (identical op streams), so every shard reports the same score. Wire: `PercolateRequest.rank` (resolved `TagId` boosts + priority key) + `PercolateReply.scores` (parallel) + a **`ranked` echo** the client checks — an old server that ignores the field fails LOUD, never a silently-unranked ordering. Handlers share the single-node `RankBody`, order `(score desc, _id asc)`, slice `from`/`size`, emit `_score`; per-slot and merged-union; `explain` stays the one 400. **Synthetic-tag boundary pinned:** a post-freeze boost fires (id-equality) but a synthetic `priority` tag contributes 0 (priority needs the value STRING only an interned tag has) — inherent to strings-die-at-the-boundary, presentation-only, documented + tested. Ranking stays post-match: ranked-id-set ≡ unranked-id-set at every K (zero FN); no `rank` ⇒ byte-identical. Oracle-proven K-swept ≡ single-node, over real gRPC, and from a reopened cluster. | Accepted |
| [076](../adr-076-cluster-multiword-aliases-vocab-shipping.md) | Multi-word aliases on a cluster (P(T)-aware routing) + the vocab-shipping decision | ADR-065 criterion 6 (the ADR-046/061 deferrals), one half shipped + one half decided-refused. **Shipped: P(T)-aware routing** — `route` derives targets from the maximal positive view when multi-word aliases are active; cover argument: a query's anchor is one of its positive features and P(T) ⊇ every parse's features (the ADR-061 parse-union property), so a satisfying title always probes the anchor's shard (zero FN); P(T)==N(T) when inactive ⇒ byte-identical. All three ADR-061 cluster refusals retired. **Found+fixed the bare-normalizer activation gap:** equivalence-driven vocabulary (declared equivalences + registry aliases, single-token included) was silently INERT on `build(norm)` and on the coordinator-mode `--vocab` startup (which dropped the loaded Vocab) — new **`ClusterEngine::build_with_vocab`** installs the equivalence machinery before extraction (the `Engine::with_vocab` order), installs + persists the vocab in the manifest from the FIRST durable commit; the server's fresh in-process build uses it. **Refused, documented: live cross-process vocab shipping** — remote-cluster vocabulary is deploy-time configuration (the ES analyzer-reindex precedent; a live remote rebuild is handoff-grade machinery and collides with the ADR-074 tag-wire boundary until criterion 9); `set_vocab` keeps the non-local refusal and the server now FAILS STARTUP on a remote assembly given ANY vocab file (equivalences would be inert AND normalizer-level rules would diverge from the shards' stock normalizer — silent cross-form FNs either way); an empty bare-manifest reopen activates the file vocab via the `set_vocab` funnel (a populated one warns). | [077](../adr-077-tagdict-recovery-fingerprint.md) | Tag-dict fingerprint in the recovery handshakes | ADR-065 criterion 9 (the deferred ADR-055 hardening): the six fingerprint-guarded RPCs (`FetchSegments`/`RecoverFrom`/`FetchTranslog`/`RetentionLease`/`Fence`/`Unfence`) verified only the FEATURE-dict fingerprint, and the bare-`connect` probe could not attest the tag space at all — a node whose tag dict diverged after adoption could serve/accept recovery traffic whose tag columns silently mis-filter. Mirror the dict pattern exactly: `tag_dict_fingerprint` on all six requests (server-side `failed_precondition` on mismatch, the same two-line guard beside the dict check), the probe reply attests BOTH spaces (a bare `connect` verifies + stores `tag_dict_fp`, presented on every guarded RPC; `RecoverFrom`'s outbound `FetchSegments` dial presents its own verified fingerprint). **Version skew loud:** a pre-077 server's probe leaves the field 0 — never equal to a real fingerprint, so the connect refuses (the ADR-075 echo principle, structurally free); the request-field asymmetry (a stale server ignoring the field) is the pre-077 status quo for that hop, gated anyway by the connect/adopt handshakes. Out of scope, documented: the self-restart sidecar (guarded by ADR-072 `tagdict.bin`), the ADR-074 tag-wire boundary (this is its named prerequisite, not a license). Fail-closed only; untagged meshes' finalized-empty fingerprints match by construction ⇒ unchanged. Guard oracle mutation-validated; all 19 gRPC oracles flow the fingerprint end-to-end. | Accepted |
| [078](../adr-078-cluster-resize.md) | Cluster resize — the auto-split mechanism | ADR-065 criterion 7 (*"the ring's `num_shards` stops being fixed at construction"*). A resize is the **`set_vocab` blue/green rebuild with the RING swapped (K→K′) instead of the normalizer**: the shared `rebuild_from_live` core re-places every live query under a fresh `HashRing::new(K′, vnodes)` — placement and routing both read the new ring (the fresh-`build` invariant), so re-placing the whole corpus is internally consistent and the hard "online ring re-keying" problem is sidestepped. Surface: `resize(K′)`, the pure `recommended_shard_count` (= K + #over-threshold shards), `resize_to_recommended`, and `POST /_cluster/resize` (write-locked like `PUT /_vocab`); the autoscaler keeps `RecommendSplit` ADVISORY (always-on auto-execution deferred — a resize is non-idempotent + `O(corpus)`, so it needs hysteresis). **In-process only** (refuses non-local/handoff, the `set_vocab` boundary; cross-process resize is the follow-on). **Durable for free** (no manifest format bump: `checkpoint` writes `num_shards`, `open` re-derives the ring + re-seeds the control plane). The one real delta vs `set_vocab` — the shard-DIRECTORY set changes — is handled: grow force-cleans new dirs + builds fresh via `new_durable` (so a stale dir from a prior shrink can't self-restart into an old corpus; divergent corpus fails loud `DictMismatch`), shrink rebuilds survivors in place + removes orphan dirs AFTER the commit (exactly `shard_000..shard_{K′-1}` on disk), the control plane is re-seeded (`ClusterStateChange::SetShardCount`), `pending_repair` is cleared, and the normalizer/vocab/tags + the dict fingerprint are preserved (invariant). Oracle-proven: resize ≡ single-node ≡ brute across grow/shrink/shrink-to-1/round-trip, broad on/off, tagged, durable reopen, and a mutation-validated delete-then-regrow no-resurrection test. | Accepted |
| [079](../adr-079-backup-restore.md) | Backup/restore — the engine-driven consistent snapshot | ADR-065 criterion 11. A *live* `cp -r` of a `data_dir` is unsafe (ADR-064 item 7): a concurrent compaction commits a new manifest then deletes the superseded `.seg`, so an external copier can capture a manifest referencing a file it missed. **Key insight:** that race exists only because the copier is external — the engine is single-writer (ADR-017, no background LSM thread), so the **engine itself** doing a manifest-driven copy under its own write-path exclusion is race-free by construction, and "restore" is just the already-oracle-proven `open()`. Surface: `Engine::backup_to(&mut self, dest)` (copies manifest-referenced segments + `sources.dat` + `wal.log`; restore replays the WAL tail), `ClusterEngine::backup_to(&self, dest)` (`checkpoint()` FIRST — the ADR-074 seam makes every shard's `sources.dat` durable — then copies the coordinator manifest + `cluster.log` + per-shard segments + `sources.dat`; replica dirs are rebuilt on open, not copied), `verify_backup`/`verify_cluster_backup` (re-open every segment via CRC-checking `MmapSegment::open`), and `POST /_backup {"dest":...}` (both modes, behind the ADR-062 default-deny gate). Atomic via sibling-staging + `durable_rename`, manifest copied LAST, pre-existing `dest` refused. Manifests are COPIED not regenerated ⇒ the v4 class-D fence + embedded dict/vocab/tag-dict survive verbatim; orphan `.seg` skipped. Trade-off recorded: the built-in path is a write-exclusion snapshot (pauses writes, not reads, for the copy); the runbook documents FS-snapshot-of-a-checkpoint'd-dir for zero-stall, and online retention-lease backup is the follow-on. Oracle-proven: single-node + cluster (K∈{1,3,8}×broad, tagged, isolation, idempotent root, fail-loud). | Accepted |

Oracle-proven: cluster ≡ single-node ≡ brute across K∈{1,3,8,16}×broad, storage-fanout-N vs read-fanout-bounded (hotspot gone), durable reopen + v5 fence + knob-off visibility. | Accepted |
