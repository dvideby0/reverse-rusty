Metadata filtering, ranking, API compatibility, aliases, and other production percolator semantics.

|---|---|---|---|
| [049](../adr-049-percolator-parity-tags.md) | Per-query metadata, filtered percolation, ranking | Per-query integer metadata tags in the SoA + filtered percolation pushed into verify (never gating, mirroring ADR-006) + optional out-of-core ranking. Built single-node + oracle-proven. | Accepted |
| [055](../adr-055-cluster-tags-filtered-percolation.md) | Tags + filtered percolation through the cluster | Thread tags end-to-end (in-process + gRPC): one shared frozen `TagDict` (like the `Dict`), raw tags in the log + read-only `get_or_synthetic` resolution (never `intern`), filter resolved once + shipped as `TagId` groups, tag-dict shipping + fingerprint handshake. Additive APIs ⇒ untagged path byte-identical. Built + oracle-proven. | Accepted |
| [059](../adr-059-percolate-ranking-pagination.md) | Percolate ranking + pagination (ADR-049 dp-4, single-node) | Opt-in post-match ranking: a new `rank.rs` scorer + `EngineSnapshot::rank` order the already-final id set by `Σ boosts + priority-tag value` (additive), tie-broken by `_id`; the handler sorts + applies `from`/`size` + emits `_score`. Adds `from` to `/_mpercolate` and per-slot truncation (closes the ADR-052 #3 tail). Touches neither index nor verifier ⇒ zero-FN; default byte-identical. Cluster ranking still deferred. Built + tested. | Accepted |
| [060](../adr-060-learned-alias-evolution.md) | Learned-alias evolution — Phase 1 (safe single-token activation) | A governing `AliasRegistry` (provenance / kind / confidence / status) over ADR-054 expansion: a structural classifier auto-activates only single-token spelling/abbreviation variants; learned category alternatives `(psa,bgs,sgc)`, multi-word, and mixed-kind groups stay review candidates. Solr/Lucene import + group-level any-of learning + the **alias-ID-stability fix** (intern active forms before resolving, so a later insert can't flip a synthetic→dense id and silently kill the alias). Active groups feed `effective_equivalence_groups`; live apply via `set_vocab`+recompile; REST `GET/POST /_vocab/aliases*`. Single-node; multi-word = Phase 2. Zero-FN; default byte-identical. Built + oracle-proven. | Accepted |
| [061](../adr-061-token-graph-multiword-aliases.md) | Token-graph multi-word aliases — Phase 2 (positive/negative title feature views) | Activates the multi-word candidates ADR-060 recorded. The wall: a title emits ONE feature set used for both required and forbidden checks, but multi-word retrieval needs the overlapping superset (unsafe for negation). Fix: **two title-side feature views** — positive superset `P(T)` (overlap-aware retrieval + required + any-of) and canonical leftmost-longest `N(T)` (forbidden only), threaded as `TitleView` through `verify`/`match_into`. Query side collapses an alias phrase to its entity (ADR-054 expansion widens it); title side is additive + overlapping. The equivalence machinery is reused unchanged (a collapsed form resolves to one entity). Forbidden policy = canonical leftmost-longest (recall-safe). Multi-word now auto-activates when declared/manual. Single-node; broad lane routes to the two-view inline path while aliases active. Zero-FN (oracle incl. forbidden-over-multi-word from day one); default byte-identical. Built + oracle-proven. | Accepted |
| [062](../adr-062-server-bearer-auth.md) | Opt-in bearer-token auth for the HTTP server's mutating/admin endpoints | The deferred ADR-052 hardening item: a single static token (`--auth-token`/`RR_AUTH_TOKEN`) enforced by one middleware (`bin/server/auth.rs`). **Default-deny** — every non-GET/HEAD request needs `Authorization: Bearer <token>` except the POST-read percolate endpoints (`/_search`, `/_mpercolate`), so a future mutating endpoint fails closed; `--auth-protect-reads` extends the gate to reads (all but `/_health`). Constant-time compare, RFC 6750 401 challenge + ES-style `security_exception` envelope, `auth_failures_total{reason}`, fail-loud config resolution, non-loopback-without-auth startup warning. Unset ⇒ byte-identical (strictly opt-in). Meilisearch/Qdrant-class single-token shape, zero new deps; TLS + gRPC auth stay Tier-3. Built + tested (unit, router-level, live). | Accepted |
| [063](../adr-063-adversarial-test-hardening.md) | Adversarial test hardening — messy corpora, reference-free properties, boundary pins | A test-escape post-mortem (every external-review-caught bug had passed a green suite) traced the escapes to too-clean generated data + the differential oracle's shared front end (ADR-050). Added: seeded **messy mode** on the generator (opt-in `messify_*`; every clean corpus byte-identical) + messy differential passes (per-title + batch); a **reference-free property suite** (`tests/adversarial/` — the self-match diagonal, metamorphic set-identity under surface noise, ADR-054/058/060/061 cross-form matrices incl. the codex-R11 whitespace-run regression, unicode-soup fuzz pinning `P(T) ⊇ N(T)` + `match_features == N(T)` + no-panic); a degenerate-input differential; posting-tier boundary units (8→9, 256→257); a WAL mid-file bit-flip pin — which **immediately caught + fixed** a real `skipped_bytes` under-count — and a delete-twice/reinsert pin. Purely additive; no hot-path change. Built + passing. | Accepted |
| [064](../adr-064-percolator-drop-in-parity-audit.md) | Drop-in percolator parity — audit findings + work package | A program ADR from a 2026-06 drop-in-replacement audit against the reference percolator workload (`research/percolator-workload.md`), including an **empirical parity PoC** — real stored queries translated under a documented parity configuration, ground truth computed by executing the reference deployment's own precision matcher: **zero FN on every pinned accepting pair**, every FP predicted. The decided work package: atomic-upsert `PUT` (✅ shipped, ADR-067), an opt-in **class-D always-candidate lane** (ES/OS treats pure-negative queries as match-all-except; ✅ shipped, ADR-068), a parity-mode normalizer knob (the `pop` year-demotion is the one residual FN class), loud non-string tag-value handling, wiring `maybe_flush` into the REST PUT path, per-request `include_broad` on `/_search`, + backlog items (restart-time measurement, backup procedure, tag read-back). | Accepted |
| [067](../adr-067-atomic-upsert-put.md) | Atomic upsert — `PUT /_doc/{id}` is replace-by-id (ES `index` semantics) | ADR-064 item 1: the re-PUT divergence (a second live copy; the id matched under either version until DELETE; `deleted_count: 2`) closed by an atomic upsert — insert the new version + tombstone every prior live copy under ONE writer critical section, ONE WAL frame (`Upsert`, op 4, WAL **v4**), ONE snapshot publish; 201-created / 200-updated. A failed replace (parse / class-D / WAL) never deletes — capture-before-insert, tombstone-after-acceptance. Replay splits by state domain over the ADR-066 watermark (insert half always; memtable priors always; segment priors only above it). Also fixed along the way: `Engine::open`'s fresh (no-manifest) path now replays the WAL tail — a start-empty server no longer silently loses every acknowledged write on its first crash (completes ADR-013's stated contract). Single-node; cluster upsert deferred to ADR-065. Built + tested. | Accepted |
| [068](../adr-068-class-d-always-candidate-lane.md) | The class-D always-candidate lane (opt-in accept-and-quarantine for negation-only queries) | ADR-064 item 2: an opt-in lane (`accept_class_d`, default off = today's loud reject) storing a negation-only query as an **always-candidate** — `anchor_plan` derives the cover of an empty positive set as ONE empty broad-anchor group (the **universal signature**, `sig_key(&[])`), probed once per segment / once per batch in the broad lane; forbidden features enforced only in exact verification (`is_pure_anchor` structurally false for class D ⇒ verify can never be skipped). The ES/OS `fixNegativeQueryIfNeeded` match-all-except + Lucene failed-extraction-bucket parity. The live write paths gate BEFORE the WAL; accepted class-D writes carry their own op codes (`InsertClassD`/`UpsertClassD`, WAL **v5**) so replay reproduces each frame's WRITER decision — legacy logged-before-classifying frames keep the old reject gate (a codex catch: replaying a legacy rejected upsert as accepted would tombstone the acknowledged-live prior version, an FN) — and a class-D-bearing commit writes segment + manifest format **v4** (layout-identical) — the manifest is the loud rollback gate (old recovery merely skips an unreadable segment; an unsupported manifest version fails `Engine::open` outright). The vocab recompile keeps stored class-D entries (closing a pre-existing silent-drop-to-unmatchable hazard); the effectively empty query (no positives, no forbidden) rejects regardless. `class_counts()[3]` now counts STORED class-D (rejections stay the separate `rejected_class_d` metric). The cluster keeps rejecting at placement — the cluster lane rides the ADR-065 replicate-broad-to-all criterion. Default byte-identical; oracle-proven (the vacuous-accept differential: per-title + batch ≡ brute, tombstones/compaction-both-variants, flush→mmap reopen + WAL replay under a flipped knob, vocab-change survival). | Accepted |
| [069](../adr-069-parity-number-context-words.md) | Parity-mode number typing — the `pop` demotion becomes a configurable number-context word list | ADR-064 item 3: the hard-coded `pop` number-context rule (a number right after `pop` demotes to `term:N`, never `year:N` — position-sensitive typing, the audit's ONE residual FN class, demonstrated in both directions) generalizes to a **number-context word list** on the shared normalizer — the ADR-058 move (hard-coded → configuration), not a boolean. Default `["pop"]` = byte-identical; an **empty list disables the rule** (the parity mode: a 4-digit year is `year:N` everywhere); custom lists work (`["qty"]`). Persisted as `Vocab.number_context: Option<Vec<String>>` (`None` = default, old JSON untouched) — applies live via the `PUT /_vocab` `set_vocab` recompile (flip-proven end-to-end, reversibly) and survives reopen through the standard vocab channels (`--vocab-file`/`open_with_vocab` single-node, the `ClusterManifest` vocab blob). The `#`/`/` context rules already ride the ADR-058 punctuation table, so after this EVERY number-context rule is configuration-controlled. The ADR-064 "emit both typings title-side" variant **evaluated + declined**: the shared normalizer + vocab-epoch recompile make mixed typing unrepresentable (nothing left to rescue), and both-typings is NOT FP-only in the single-view path (it flips forbidden-year outcomes under a `Marker` `#`) unless forced through the ADR-061 dual-view — a hot-path cost for an empty case. Trade pinned: with graders configured, disabling the rule makes `psa pop 7` read as a grade (the parity config has no graders). Oracle-proven (engine ≡ brute under the knob incl. forbidden/any-of; both audit directions closed + default contrast). | Accepted |
| [073](../adr-073-rest-parity-hardening.md) | REST surface honesty — tag-value coercion, flush wiring, per-request broad | ADR-064 items **4–6** in one hardening batch (the ADR-052 precedent): **(4)** non-string tag values — silently dropped on ingest and in filter arrays (corrupting filtered percolation invisibly: the query became unreachable by any filter on that key) — now take **canonical scalar coercion** (number/bool → JSON text, the ES keyword behavior; ONE shared function on ingest + both filter parsers so the sides can never disagree; `7.0` → `"7.0"` pinned as in ES), null = the ES "no value" (skipped on ingest, **400 in a filter** — an unanswerable predicate never silently widens), objects/nested arrays/non-object `tags` = loud 400 everywhere (`/_bulk` per-item; cluster mode shares the same helpers). Coerce-over-reject because the reference workload's dominant filter key is a numeric category — a drop-in that 400s payloads the reference accepted is not a drop-in. **(5)** `memtable_flush_threshold` was inert for REST single-doc writes (`put_doc` bypassed the only `maybe_flush` site) — the knob now lives at the success tail of BOTH fallible live-write paths (never on rejected writes; replay/bulk/cluster funnels deliberately untouched). **(6)** `/_search` gains the per-request `include_broad` override `/_mpercolate` + the cluster handlers already had (the body field was silently swallowed); `deny_unknown_fields` declined — sibling-tag ingest depends on tolerance. Nothing touches signature gating; absent/unset ⇒ byte-identical. Handler-proven incl. the ingest-meets-filter agreement. | Accepted |
